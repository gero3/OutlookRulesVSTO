# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or include secrets,
personal data, or exploit details in a pull request. Use GitHub's private
security-advisory form for this repository so the report remains confidential.

Include the affected version or commit, reproduction steps, impact, and any
suggested mitigation. Credentials exposed accidentally should be revoked before
the report is submitted; removing them from Git history is not a substitute for
revocation.

## Supported version

Only the latest commit on `main` is supported. Security fixes are delivered on
`main` and should be installed through the next signed release.
