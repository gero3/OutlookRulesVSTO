OutlookRulesVSTO

Developer and operator guide for the Outlook Classic add-in that automatically files messages and attachments using configurable rules.

OverviewRequirementsBuildInstallUseConfigurationArchitectureSecurityTestingTroubleshootingRepository

Overview

OutlookRulesVSTO watches the Inbox in Outlook Classic, evaluates messages against XML rules, and saves matching attachments or message content to configured Windows folders. The Outlook ribbon also supports dry runs, manual processing, rule management, and locally generated rule drafts.

Supported launch path: Outlook Classic → OutlookRulesVSTO VSTO add-in. There is no supported command-line, Visual Basic macro, standalone desktop, or directly hosted web entry point.

Requirements

  • Windows 10 or later.
  • Microsoft Outlook Classic desktop, with a bitness matching deployment prerequisites.
  • Visual Studio 2022 with .NET desktop and Office/SharePoint development workloads.
  • .NET 10 SDK for supporting projects and .NET Framework 4.7.2 developer pack for VSTO.
  • VSTO Runtime and Microsoft Edge WebView2 Runtime for deployed installations.

Build from source

  1. Clone the private repository.
  2. Open OutlookRulesVSTO.slnx in Visual Studio.
  3. Restore NuGet packages and build Release | Any CPU.
  4. Set OutlookRulesVSTO.Vsto as the startup project.
  5. Start debugging. Visual Studio registers the add-in and launches Outlook.

The VSTO project requires Visual Studio/MSBuild Office targets and should not be treated as a portable dotnet build project.

Installation

Production deployment uses the WiX installer under installer/. Set OUTLOOKRULESVSTO_SIGNING_CERT_THUMBPRINT to a trusted certificate in Cert:\CurrentUser\My; the package script signs the VSTO manifests and exports the public publisher certificate. Do not commit certificates or private keys. Close Outlook, install with administrator rights, then restart Outlook and confirm the OutlookRulesVSTO ribbon group is visible.

Uninstall

Close Outlook and uninstall OutlookRulesVSTO from Windows Installed Apps. User configuration under %APPDATA%\OutlookRulesVSTO is intentionally retained unless removed manually.

Using the add-in

Ribbon actionPurpose
OutlookRulesVSTO openenOpens the authenticated rule-management interface.
AI-regel uit selectieBuilds a local draft rule from the selected message.
Test selectieEvaluates selected messages without saving files.
Verwerk selectieEvaluates and saves files for selected messages.

Incoming messages are evaluated automatically while Outlook and the add-in are running.

Configuration

Runtime configuration lives in %APPDATA%\OutlookRulesVSTO. settings.xml controls paths and behavior; rules.xml contains ordered conditions, extraction expressions, and destinations. Start with files in sample-config/, test changes with the dry-run ribbon action, and keep destination folders within locations the signed-in user can write.

Back up both XML files before bulk edits. XML is validated before accepted UI changes are written and saves are performed atomically.

Architecture

Outlook adapterThe deliberately tiny untestable edge. It hooks VSTO/Outlook events and translates MailItem properties, attachments, and save calls into neutral interfaces.
ApplicationA host-independent, dependency-injected workflow for selection handling, rule evaluation, save-plan execution, result construction, logging, and desktop handoff. This layer targets .NET Standard 2.0 so both VSTO and the automated tests consume the same code.
Desktop/WebPrivate, token-gated UI helper started and stopped through an injected gateway. It is not an independent application.
CoreRule model, XML persistence, matching, extraction, validation, and logging.
COM bridgeInternal compatibility adapter used by the .NET Framework VSTO assembly to call the modern rule engine; no macro workflow is shipped.

Security model

  • The helper requires a high-entropy token created by VSTO and passed through the process environment.
  • The local HTTP service binds to loopback only. Outlook bridge requests use a constant-time token comparison.
  • Direct helper launches without the VSTO token terminate immediately.
  • Rule paths and output permissions remain under the Windows user account.
  • Signing secrets, generated binaries, models, runtime downloads, IDE state, and logs are excluded from Git.

Testing and coverage

.\scripts\test-coverage.ps1

The coverage command runs both managed test suites, merges their Cobertura data, writes an HTML report to TestResults\coverage\report\index.html, and fails below 90% line or 70% branch coverage for the Application, Core, Web, and COM bridge assemblies. Full-flow application tests inject fake mail, filesystem, rule-engine, desktop, and logging adapters and exercise the path from an incoming or selected message through evaluation and saving to the final result. Only VSTO event registration and direct Outlook COM translation remain outside that automated flow. Generated VSTO designer code, Outlook/Windows UI host code, and installer custom actions are build- and integration-tested separately because they require their native host processes. External local-model download, llama.cpp supervision, and inference are exercised by the opt-in AI E2E suite because they require the optional multi-gigabyte model.

VSTO integration testing additionally requires Windows, Outlook Classic, and Visual Studio Office tooling. Before release, test add-in startup, automatic Inbox handling, all four ribbon actions, invalid XML, unavailable destinations, helper shutdown, and both supported Office bitness deployments.

Troubleshooting

Ribbon is missing

In Outlook, inspect File → Options → Add-ins. Re-enable the add-in if Outlook marked it inactive, then verify the VSTO Runtime and manifest trust.

Rules or settings are missing

Open OutlookRulesVSTO from the Outlook ribbon and save configuration, or copy the samples into %APPDATA%\OutlookRulesVSTO.

Rule manager does not open

Confirm WebView2 Runtime is installed. End orphaned OutlookRulesVSTO helper processes, restart Outlook, and inspect application logs in the configured log folder.

Files are not saved

Use Test selectie, verify the matched destination, then check folder permissions, path length, filename validity, and whether the attachment is inline.

Repository policy

The repository is private and source-only. Generated installers, binaries, downloaded AI models and runtimes, coverage results, certificates, and per-user Visual Studio files are never committed. Changes should keep VSTO as the only supported launch path and update this document whenever operator-visible behavior changes.
